# Definition of Done

Робота вважається завершеною, лише коли виконано **всі** пункти нижче.
Автоматичні перевірки описані в [`checks.md`](checks.md).

## 1. Код і конвеєр

- make check проходить без помилок (формат, лінтер, тести, збірка).
- Git-hook не обходили (--no-verify не використовувався).
- У src/ немає закоментованого коду, зайвих файлів і console.log.
- Залежності зафіксовані в package-lock.json; секрети й .env не потрапили в репозиторій.

## 2. Spec і тести

- Будь-яка зміна поведінки спершу описана в `spec.md`, а вже потім у коді.
- spec.md узгоджений з ADR (модулі, стек, БД, автентифікація).
- spec.md відповідає формату зі standards/spec-format.md.

## 3. Архітектура

- Структура src/ відповідає модулям зі spec (auth, tasks).
- Модулі взаємодіють лише через публічний інтерфейс (index.js); заборонені залежності з розділу 3 spec відсутні.
- Автоматична перевірка меж модулів входить до make check.

## 4. Рішення та аудит

- Кожне ключове рішення має ADR за шаблоном із щонайменше двома розглянутими альтернативами.
- Прийнятий ADR не переписується: зміна рішення оформлюється новим ADR зі статусом заміни.
- Аудит проведено: топ-3 розбіжності зі spec виправлені зміною spec, критеріїв або стандарту, а не ручним патчем.

## 5. Безпека

- Паролі зберігаються лише як хеші, у логах їх немає.
- user_id для операцій із завданнями береться лише із сесії, а власник перевіряється для кожної операції.
- Внутрішні помилки не розкривають деталей реалізації користувачу.

## 6. Слід AI

- Суттєві взаємодії з AI збережені в ai/ за шаблоном ai-interaction-template.md.
- У кожному записі заповнено My Feedback: що прийнято, що змінено і чому.
- Для кожної з топ-3 розбіжностей є посилання на промпт, фідбек-коментар і коміт зі зміною spec чи стандарту.

## 7. Репозиторій і здача

- Історія складається з дрібних змістовних комітів (feature-branch → PR → merge).
- git status чистий, у PR немає сторонніх файлів.
